# 从一批材料到共同形成的故事

适用于作者不知道画什么、不确定自己的逻辑如何用图表达、或只有零散结果的情况。正常起点是材料与困惑，不是图型名称、期刊配色或完整的story brief。新项目`init`会生成可空缺的`story.json`和`scripts/story.py`；宿主代理负责理解材料与协作，CLI负责保留讨论、依赖和可检查的产物，不调用模型也不自动提炼科学结论。

## 先帮助人理解自己想表达什么

先读可取得的结果、文字、图、日志和论文。用户说不清故事时，不反复追问“你想讲什么故事”。可先回应：“我看到材料可能支持这几种问题……”并给有依据、实质不同的解释供其纠正。一个有用的问题是“哪一个更接近你觉得重要的地方”；也可请其指一处意外结果或担忧。人不必先知道图种、机制术语或最终结论。一次问会改变下一步的关键问题，能独立做的来源整理和草图继续。

若用户只提供目标或参考文献，没有本项目研究结果，仍可归纳领域问题、做表达草图和材料需求清单；把own_results_status保留not_provided。文献结果可以支撑文献综合，图例可以提供表达参考，都不能自动成为用户的创新或本项目结果。

## 把模糊意图变成可讨论的逻辑

将绘图视为把意图编译为图形语言。编译前先区分：用户想表达的意义、材料支持的事实、代理建议的组织方式。不要把自己的解释悄悄写成用户意图。沿用 `brief.user_intent` 保存当前意图摘要，用户原话和修正保存在 `decisions.verbatim`；候选继续保留 `proposed_by`。意图摘要可以由代理提出，但须注明它是解释还是已明确表达的要求。

一次有用的协作循环是：

1. **回述含义**：用材料语言说明“我理解你希望读者认识到……，其中关键区别是……”。只指出会影响叙事的歧义，不让用户填一长张表。
2. **试探逻辑**：把现有结果连成“问题 → 关键对照/观察 → 解释 → 边界”，指出哪一跳缺证据、混淆相关与因果、缺公平对照或存在另一解释。无法支持的结论，提出缩小主张、补证据或另换问题的具体方案；不只美化措辞。
3. **比较真正不同的故事**：候选说明看完后读者得到什么判断、依靠哪些材料、牺牲哪些重点。选图之前就比较，例如“证明平均性能更好”与“说明何时可以托付研究、何时应限制结论”需要不同证据，不能只换标题。
4. **编译为面板**：每一步接入现有的 `reader_question / observation_ids / panel_ids / paragraph_job`。再选择对照、分支、空间关系、尺度变化等图形语法，说明其理由。不能从素材数量推导必须有同样数量的面板。
5. **从图反读故事**：隐藏设计说明，仅看图与正常图注，复述它实际表达的结论，再与用户意图和证据边界对照。若视觉重心、箭头或顺序把“有条件可靠”读成“始终成功”，回到逻辑和编码层修订。设计者自查与独立读者测试分别记录，不能互相冒充。

用户纠正“不是这个意思”时，先说明误解发生在目标、证据解释、叙事顺序还是视觉编码，更新对应项并指出受影响的面板/正文。用户只调整字体时，不重开已明确的主线。新证据推翻原解释时，即使版式已经精美，也应重新讨论主张；逻辑审阅不是一次完成后永久放行的阶段。

已有明确意图就继续执行，不把本节变成强制审批仪式。尚不明确时可用代理推荐的候选推进可逆草图，同时保持 `selection:null`；不要让“继续”自动成为科学主张的确认。

## 批量拆解与归纳的最小实质

以论文版本家族去重，区分实际读到的范围。每篇先提取：研究问题、作者想改变的认识、关键比较/对照、真实观察、作者解释、范围与替代解释；再记录各图的读者动作及在证据链中的作用。每条观察保留paper_id和原文/图注定位，basis分source_observation/source_interpretation/assistant_inference；use分scientific_evidence/visual_reference/literature_synthesis。

跨论文归纳围绕共同问题：哪些比较在回答同一件事，哪些结论相互补充或冲突，哪些差别其实来自体系/温度/电位/训练集/单位/误差定义。把“领域的科学规律”与“论文怎样把一个判断表达清楚”分别归纳。相似图型不代表相同问题；不同条件下的MAE、吸附能、TOF等不能凑成统一排行榜。定量综合需要可比性和分析依据；不具备时用分面、条件表或质性证据地图。

## 共同收敛故事，而非替作者下结论

从当前材料提出少量有实质差别的候选：读者原来怎样理解、看完以后能判断什么、核心问题、认识推进顺序、所需主张/支持/反证、还缺什么。候选之间可以是“解释为什么”“识别何时失效”“比较哪些因素真正有用”，不只是同一故事的不同布局。尽量用材料语言，保留作者可以反对的具体判断。

在story.json中连接`candidate.steps → reader_question → observation_ids → panel_ids → paragraph_job`。候选标明提出者；作者尚未选择，selection为null。用户觉得某个配色好看或说“继续”不等于选择了科学故事；用户选择也不等于支持证据成立。decisions保留真实原话、范围及动作，CLI中的origin只是声明，宿主仍须核对真实对话。不能编写假的用户偏好或让页面按钮自动把反馈升级为定稿。

## 让图服务读者动作

先写“读者要比较/辨认/追踪/排除/估计什么”，再提图型与构图候选，同时解释为什么。几个常见问题：

- 比较改善：同一测试集、单位与统计口径下的配对/散点/误差分布；不只有一个平均数。
- 判断何时可用：误差和适用条件对应的动力学/自由能/结构/物性验证，必要时展示反例；缺任务级数据则留空，不画假曲线。
- 讨论机理：对象与物质/电子流的示意，加支撑这些关系的证据面板；未排除路径明确并列。流程箭头不证明因果。
- 描述筛选决策：候选空间、筛选边界/代价、关键反证和验证；不是仅画漏斗表示必然成功。
- 解释分析单位：可用一个来源明确的实际例子，贯穿采样对象、重复身份、测量结果与分组单位，让读者沿位置或身份对应恢复“哪些结果属于同一比较”。概览只画实验步骤、总数与状态图例时，先检查这条对应是否真的出现；这是一种针对分组/重复问题的可选构图方法，不要求所有Fig1都采用流程或矩阵。
- 精确查值：表格；读趋势或关系：相应曲线/分布/结构对照。图种仍依具体材料判断。

同一证据可先做不同阅读顺序的草图，让作者用“这不符合我的意思”“我想强调这个对照”“这里容易误会”反馈。草图注明是探索、文献重绘还是项目结果，说明它强调和隐藏什么。可美化的源对象和不可改变的数据/科学限定分开。题目/主图/补图分工和段落推进一同修订；不是做完漂亮图后再替它编故事。

## 可运行交接

```bash
python scripts/story.py check story.json --project research.json --out reports/story-check.json
python scripts/story.py brief story.json --out story-discussion.md
python scripts/story.py board story.json --out story-board.html
python scripts/story.py impact story.json OChanged --out reports/story-impact.json
```

board是本地讨论页面，显示故事候选、面板用途、可用预览和缺口，可导出原话反馈供下一轮讨论；它不自动运行代理或保存用户选择。输入材料变化时重新读源并审阅受影响的解释与顺序。`research.json.story_plan`把讨论文件纳入图件输入指纹；story的source snapshot变化可提示重开依赖，不能自动证明新旧结论是否正确。

已有argument-architect状态库时以其source/evidence/claim/plan为科学主状态，story.json只作视觉讨论与尚未决定的探索视图，复用稳定ID与定位。选定后再按其plan/正文补丁流程交接；不并行维护另一套相互冲突的已支持主张。没有该状态库时可在小项目直接维护本文件。验收需要实际材料驱动的推理与作者反馈，不能靠JSON完整或页面存在声称已形成好故事。


## 批量定位与真实拆解的分工

对已合法取得的本地 JATS XML，可先运行 `python scripts/paper_batch.py batch-manifest.json --out figure-inventory.json`。manifest 的 papers 列表给 `id, doi, path`，path相对manifest所在目录。该命令批量定位图注、图件ID及正文引用段落，保留原文定位与文件版本；输出的 reader_task/argument_role/comparison_or_control/scope_and_alternatives 刻意留空，review_status仍为text_extracted_not_interpreted。它不是读过原图、完整拆解或科学核验。宿主随后查看实际图像与相邻文字，对照这些槽位解释读者路径，再把相关观察接入story候选；不把图注关键词当成科学理解。

覆盖按领域和读者动作盘点：总览/框架、模型架构、分子—周期结构衔接、机理、PES投影、反应网络、多路径能量图、定量比较/分布/学习曲线与表。不要强迫每项都画，也不要让某一领域常见的单一模板替代其他任务。未有真实案例的项保留缺口。

反应网络必须分清物种/构型/集合节点，边是候选转化、轨迹事件还是经过TS验证的步骤；筛选前后保持ID和位置便于追踪删除。台阶图须声明能量类型与共同参照，映射共享中间体、分支、循环、过渡态及条件；ΔE不是ΔG‡，未知TS不能自动画峰。高维PES只能通过明确坐标的切片/投影/等值面等呈现，说明冻结/积分掉的自由度和采样范围；装饰曲面不能承担数值论证。
