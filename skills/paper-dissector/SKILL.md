拆解表达如何服务论证。先读 [共享数据契约](../argument-architect/references/contract.md)，需要细粒度标注时读 [拆解规范](references/dissection.md)。

## 输入

已登记来源及可定位的全文文本；可接受局部段落或图注任务。没有全文时只分析实际可见部分，保留访问和解析限制。

## 逐步加深

先做宏观筛选：文章想改变读者的什么认识、贡献相对谁成立、证据路径是什么。对代表性或当前问题相关的部分，再拆主张—证据—推理依据—假设—替代解释。需要学习具体表达时再拆到段落或分句；不预设所有候选论文都要逐句分析。

全文看核心问题和贡献边界；章节/图表看读者依次需要回答的问题；段落看输入背景和输出认识；分句允许 observation、interpretation、qualification、contrast 等多标签。一句话可同时包含结果与解释，不强制单一 move。

标注 analysis_status 为 explicit 或 inferred。原作者认为证据支持某机制，不代表该机制已经排除竞争解释。提取作者立场与评价该立场分别记录；未评价用 not_assessed，分歧和未知保留。

## 输出与核查

按 dissection.schema.json 输出，span 使用 UTF-8 文本快照的 Python 字符索引（start 含、end 不含），document_sha256 来自原始字节。附 section/page/figure 等人可读定位。运行 `put dissection` 检查当前快照、引文和区间是否一致。

概括 novelty 时列出最近工作、已解决问题、残余限制、本工作改变的维度、对应结果与未解决问题。有限检索不能支持“从未有人研究”。原文片段按需引用，避免把整篇材料复制成技能资产。

统计只描述当前样本；给出样本量和选择偏差，不能按 move 频率生成硬性要求。抽检覆盖标签边界、少数类与分歧，再决定是否增加样本。
