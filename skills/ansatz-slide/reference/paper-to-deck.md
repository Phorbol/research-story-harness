# 一篇论文到完整汇报

适用于用户给 PDF、论文链接或正文，要求一套汇报；这是现有技能的入口，不是单独的论文专用技能。已有 brief/story/claims 时继承它们，没有时由制作代理从论文建立，不把准备工作推回用户。

## 输入与讲述任务

先识别论文实际标题、版本、正文／SI是否齐全，以及用户已给的听众、语言、时长和用途。内容与文件名冲突时以文件内版本为准。缺少偏好但不妨碍制作时，说明采用的默认：按对话语言，面向相关领域研究者，约15–20分钟；页数服从论证而非凑固定数量。只有会改变结论、受众知识前提或范围的缺口才询问，并继续不依赖答案的工作。

输出项目保存原PDF或链接版本、按PDF页码定位的文本和图表来源。可复用 scientific-figure 的 reference_intake.py 提取选定页面，或 PDF 技能的现有工具；解析记录只是未审阅材料。读完整研究正文与相关图注，实际查看关键图、表和附录页，不能只靠摘要或文本提取推断布局与图中数据。未提供SI、坐标或原始数值时保留缺口，不把“文中说有数据”当作已经取得。

## 从论文组织讲述

在项目内形成一份共享的最小 story/claims 与页码映射，后续页面引用它。先回答：为什么这个问题值得解决；现有做法在哪个具体场景不足；本文改变了什么；哪组证据能区分解释；结果允许读者做什么判断，在哪些地方还不能判断。

论文有多个合理侧重时比较候选，再自主选择与用户用途相符的一项并标记为制作假设。不要把目录逐项变成页面，也不要把“一张原图对应一页”当成完整汇报。以听众需要解决的问题选择讲述路径：可从未解释现象、关键对照、方法瓶颈或结果预告切入，不固定为论文的章节顺序或统一的背景—方法—结果模板。推导、全基线和额外诊断可放备份页，但不能把支撑中心判断所需的解释桥梁一起移走。

草稿中的待补结果、占位表和未定作者不得编造成完成状态。尤其区分原文结果、作者解释、汇报者归纳和下一步计划。性能比较保留输入条件、分母、基线、成本口径和不确定性；未显著的消融、负结果和内部冲突不能在压缩时变成积极贡献。

## 把讲述计划变成可试讲的源稿

先辨贡献与取舍：原问题、方法必要性、关键证据、验证／反例及结论范围，决定主讲、简述、备份或省略。忠于论文是保留主张与证据的依赖，不是复刻作者页序。以下直接写入现有页纲和 source-map，不另建一份平行事实台账。

**连接写听众的推理，不写邻页标题。** 在最难转折的 `previousConnection` / `nextConnection` 中写实际尚未解决的问题，以及当前证据为何让下一步成为必要；复制前后页标题不是解释。首次关键对象或观测量用正常讲稿给出“它对应哪个对象／操作，图上怎样读，为什么这个变化支持判断”。词典式定义不必单列成页：可把一个必要对象、参照或方向直接绑定主图。听众已经知道的前提无需重复教学。

**先取完整的条件句，再压缩标题。** 对本次会说出的结果，从正文、图注和对应方法取得“什么对象／数据，在什么筛选或处理下，相对哪个对照，得到什么，允许什么判断”。来源位置挂到同一结果上；泛指一整节或末尾一句“有局限”不能代替。条件尚未找到时回原文，不让编译器替你猜。有多个样本、模型或处理流程时保留各自身份，不因用了同一方法就称同一批数据。改变上屏结论含义的限定贴近相应图或数值；只在口述中使用的比较，也在该句口述内说清条件。

正常讲稿可直接用现有 `notes`；条件多、容易在投影中丢失时，可在 source-map 的相应 page 使用有序 `notes_blocks`，由 `scripts/compose_talk.py` 生成同一份 `notes`，供页面源和讲稿共同消费。它不读取论文、不判断条件是否齐全，也不自动把限定放到页面。

```json
{"pages":[{"id":"S09","title":"实时控制与条件对照","notes_blocks":[
  {"kind":"definition","spoken":"先区分实时改变后续操作，与最终只选择部分结果。"},
  {"kind":"evidence","source":"Bluvstein et al., Nature 2024, PDF p.5 Fig.4e caption",
   "spoken":"实时前馈的77(2)%与关闭中途读出、并在最终读出时后选择中间逻辑为正号态 |+L⟩ 的75(2)%对照相近；后者不是无条件基线。",
   "visible_text":"实时前馈；对照含最终后选择"},
  {"kind":"transition","spoken":"这表明控制能接上测量；更严格的筛选能改善多少，还要与丢弃的数据比例一起判断。"}
]}]}
```

这是已核源的局部制作示例，不是新论文的布局或必讲主题。`spoken` 是实际口述，`source` 是制作侧定位，`visible_text` 是拟上屏短句，仍须由页面制作采用并在真实图面核对。其他计划字段保留但不混进讲稿。普通 `notes` 页可与分块页混用；同页不同时保存二者，避免旧讲稿被静默覆盖。

```bash
python3 <ansatz-slide>/scripts/compose_talk.py source-map-input.json --out talk-v1
# 用 talk-v1/source-map.json 中的 page.notes 写入现有页面 YAML；
# speaker-notes.md 用于正常顺讲，evidence-projection.md 用于返回原文逐项比对。
```

**在首稿前连续试讲最难的一段。** 完成页纲后选前提最多、观察量变化最大或后段最压缩的连续页面，用候选画面和正常讲稿按顺序读：上一页留下什么问题，眼前哪个对象接住它，如何从图中得到下一判断。需要时用真实试页，不用孤立易页代替。发现断点就回改同一页纲／讲稿／画面：补一条读图钥匙、重排证据、减去支线或让关键对象占主视觉，按时长取舍，不默认加页。保留试读前后及修改原因；首次方案创建不算返工，但修改已写出的故事、图面和素材都计入首稿前工作。

最后对完整成品分开判断：是否忠于论文的贡献与条件；指定听众能否按正常讲述跟上；科学主角、对照和主次是否在实际画面成立。源记录完整、朗读顺口或编译成功都不能替代三项判断。科学条件核查须回来源，不只检查它是否从输入复制到了输出。

## 把证据变成适合讲述的画面

- 结构／机制／PES示意说明对象与关系，数据图承担定量判断。选择原图分面、局部放大、按可靠表值重绘或新的概念示意，各自标明来源身份。不要把全部证据缩贴成难读的小图。
- 只有图像而无数值时，优先清晰复用原面板；不能为了可编辑而估造曲线、误差或轨迹。复用图的坐标轴、图例和限定需要在最终页面仍可读。
- 机制/状态/架构页先落实[关系追踪与编辑层级](../../research-harness/references/relations-and-editability.md)，区分共同输出、竞争分支与循环恢复；不要仅给关系名却让读者自行补连接。
- 科学主角应占据视觉重心：反应位点、请求方向、对比曲线或模型结构。少量流程页可说明执行次序，但不能用同一串框箭头替代所有原理、机制和结果页。
- 固定演示尺寸、字体和语义色；在最终PPTX导出中检查整页阅读与局部标签。制作说明、裁切操作和版本日志留在源记录；影响解释的来源与限制留在科学页面。

## 真正执行与交付

依照 production.md 与 CLI文档制作有序页面，使用现有 deck preflight、import-pages、revise 和 export；不绕开现有渲染链再造一个导出器。把共享主张与页源绑定到投影映射和讲者备注。对实际渲染逐页阅读：关键图是否解释本页判断、页与页是否推进、正常全屏是否能读单位／误差／结构关系；无碰撞只是必要条件，不是审美验收。

交付完整PPTX、对应PDF、页面源与素材、可重建说明，以及简洁的主线／讲述提示。原生文字和形状可编辑、分子或源图为图片时如实说明。用户要求独立评审时，另一个上下文先读成品再读预设故事；未经独立评审不冒称盲读通过。实际缺陷回到源页面修复后复看受影响页；测试和元数据不能代替成品观察。

完整汇报需要按正常讲述顺序检查方法、模型、验证与解释之间的连接，并分别核对机制图和最终 PPT 内的编辑能力。修订后可接受的案例不能证明任意新论文首稿自动达标。
