# 学术写作

目标是让读者看清研究问题、证据如何支持结论，以及结论的边界。沿用用户的语言、稿件结构和期刊要求；局部润色不强制重建整个项目。

## 工作方式

1. 读取现有稿件、数据说明、参考文献与项目指令。辨认任务是探索问题、组织论证、起草、局部修改还是审稿回复。没有结果时保留问题与候选解释，不预设成功故事。
2. 对需要新增或改变的科学主张建立台账：`id / text / status / evidence_ids / figure_ids / scope / limitations / alternatives`。`status` 区分 `supported / hypothesis / contested / unknown`；来源声明与作者推断分开。缺证据时缩小措辞或显式留空，不补造数值、显著性、引用或机制。
3. 作者可能还不知道画什么或怎样组织结果。先从材料提出可讨论的认识变化、比较和困惑，给具体候选帮助其辨认本意；不要求其先交一份完整story brief。用草图反馈共同调整图件与段落。故事不清楚时，先从同一证据建立不同论证路径，并说明各自支持范围与材料缺口；用一个高影响问题引导用户选择，沿用已有偏好。写作和绘图共同维护 story/claim/evidence/panel/paragraph 对应。用“读者问题 → 主张 → 证据及反证 → 图表 → 段落”组织论文。先确认 Results 的推进及主图/补充材料分工，再按任务起草所需部分；不强制固定写作顺序。
4. 每段承担一个明确论证作用；区分观察、计算、解释、假设和泛化。与参考研究比较时核对条件、分母、误差定义和适用范围。保留未排除的替代解释。
5. 与绘图共享稳定的来源、主张、图件和对象 ID。正文引用、图注、图表数字、单位、条件与主张强度一起修改。引用到面板而非模糊的“如下图”。
6. 收尾报告实际改动、证据缺口和已完成检查。语言流畅不等于论证通过；自动链接检查不等于事实核验。

详见 [写作与修改](references/writing.md)：用于论文大纲、图注、审稿回复和跨文件修改。已有项目使用其格式；需要建立可执行项目时配合 `$research-harness`，绘图配合 `$scientific-figure`。缺少这些 skill 时直接维护上述台账和现有文件，不安装未知依赖或改动全局配置。

正文与图件使用共同的术语、公式、化学式、单位和符号约定。字体、颜色、加粗与斜体遵循项目 style profile；跨正文/图注发生单位或限定语变更时同步修改，不能只润色文字。对图件方法比较先固定证据与主张，再比较叙事组织；不得把美观偏好表述为经过独立读者验证的结论。
