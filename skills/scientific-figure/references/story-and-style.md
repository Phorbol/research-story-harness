# 故事、图表和美观的协作顺序

## 1. 先知道讲什么

材料可能是论文全文、用户段落、零散图片、数据或结构文件。先建立材料表：来源与版本、具体对象、观察/计算/解释、可支持的主张、相互矛盾或缺失处。检索到一篇文章不等于获得其数据或赞同其结论；同一研究的预印本与期刊版属于一个版本家族。

用两句话表达：读者原来不知道什么；看完哪些证据后可以判断什么。若故事未定，提出证据确实支持的不同路径，如“方法怎样工作”“两种对象有何差别”“预测如何获得验证”，说明各自需要的材料和不能说的结论。问用户一个会改变叙事方向的问题，其余工作继续；已有偏好直接沿用。用户尚未选定时保留候选和代理建议，不能伪造用户选择。

绘图是意图到图形语言的编译，而不只是素材排版。先回述用户含义，主动诊断逻辑跳跃、反证和替代解释，再比较叙事候选。成图后从图反读其实际表达，与用户意图核对；错位时先修逻辑/编码，不能只换颜色。具体协作循环见 harness 的 [故事共构](../../research-harness/references/story-discovery.md)。

## 2. 决定用什么图表

建立 `reader_question → claim_ids → evidence_ids → visual_task → panel/table → paragraph` 映射。图种按判断任务选：配对变化、分布、趋势、误差/拟合、矩阵/热图、网络、流程、结构、能量/反应、表格、TOC。表格适合精确查值，曲线适合走势；流程依赖不能代替定量证据。

复杂图比较真正不同的布局：过程线性、对象为中心、对照并列、尺度递进、证据收束。固定数据、限定语与语义色，使比较主要来自阅读路径；配色变化另作为风格比较，不能冒充新故事。先用少量真实材料做低保真布局，检验缺什么证据，再投入高质量结构渲染。

## 3. 再做到美观

检索顺序是科学任务和对象 → 布局 → 风格。从实际图、图注及正文定位形成六层参考卡；可迁移留白、对齐、编码与分组，不能移植别人结构身份、实验数字、误差定义或机制。期刊名称只是检索条件，不是正确性或统一美学的保证。

本包 `assets/reference-library.json` 是一次有界调研的真实状态：区分已目视的具体图件、只解析文件、只有元数据/访问失败。它不是全部期刊的代表性抽样，也不是所有原图的像素复刻。三维结构和三种 TOC 的实证迁移见 MatterGen 案例；其他卡目前是观察与设计建议。

参考提取依赖见 `assets/requirements-reference.txt`（PyMuPDF，安装到项目隔离环境）。新增 PDF 可运行 `scripts/reference_intake.py paper.pdf --pages 2,3 --out reference-work/paper`。脚本提取页面、原文文字与 PDF 文本属性，并创建 **unassessed** 卡；必须打开实际页面后才改观察状态。HTML/登录页伪装 PDF 会被拒绝。PDF 字体属性包含正文与图注，须圈定图区域后再讨论图内字体；矢量转曲和图片内字不能由文本提取恢复。

## 统一文字与科学颜色

在项目级 `style-profile.json` 定义字体、正文/标题/面板/轴/刻度/图例/脚注/变量角色；同一角色跨图统一字体、物理字号、颜色、字重和斜体。元素、化学式、单位通常正体，数量变量按语义斜体，化学计量/电荷用正确上下标；不能把整个化学式设成数学默认斜体。加粗承担明确层级或预先声明的突出规则，不随手加粗“最好”的数。

元素色、方法色、实验组色、连续量色标分开命名；颜色跨图保持含义。图注说明混合占据色/符号；灰度或色觉受限时还用线型、标记或直接标注。最终以实际刊载尺寸检查文字，检查缩放后的线宽、图例密度、基线/小数点对齐、长标题、裁剪和标签碰撞。

当前 harness 审计真实 Matplotlib 文本属性与可用字体、保存字体解析结果；不自动验证数学含义、阅读理解、所有碰撞或外部软件添加的文字。主图应能承载轴/单位；TOC 内的紧凑 sparkline 仅为摘要缩略视图，并指向完整数据图，不能用缩略图直接读精确数值。

对反复出现的字体与版式漂移，先检查绘图代码是否真的使用样式配置。独立 recipe 和复制来的图式也要暴露同一处字体、物理字号、字重与语义颜色入口；不要只给配置文件留一个未使用的字段。自定义图式若仍在代码里复制配色常量，可在临时副本只改一项配置，检查相应图元确实改变、无关对象保持，随后使用原正式配置导出；这验证编辑入口，不评价配色审美，也无需扩为所有图的固定测试。`style_figure` 统一呈现，`typography_audit` 检查实际属性；显式但不存在的文字角色应失败，不能静默当正文通过。默认正文角色的存在不证明代理已正确区分所有文本语义。

混排按片段处理：变量 $T$、$G$ 斜体，单位 K、eV 与化学符号正体；描述性下标用正体（如 $E_{\mathrm{ads}}$），变量或索引下标按其语义处理。面板字母可用粗体，是否加粗标题是项目设计选择；向量/矩阵的粗体含义与标题强调分开。不把整条轴标题或整段反应式设成斜体。依据：[NIST SI 符号规范 §10](https://www.nist.gov/pml/special-publication-811/nist-guide-si-chapter-10-more-printing-and-using-symbols-and-numbers)、[单位规范 §6](https://www.nist.gov/pml/special-publication-811/nist-guide-si-chapter-6-rules-and-style-conventions-printing-and-using)（2026-11-09核查）。最终字号服从目标用途；[Nature 官方图件要求](https://research-figure-guide.nature.com/figures/preparing-figures-our-specifications/)中的字号范围仅适用于其要求，不提升为本 harness 通用默认。

所有后端导出 `.layout.json` 的文字边界、越界和箭头穿字候选，数据图也不例外。优先改分面、锚点、留白、刻度密度和说明位置，再考虑字号；尤其检查对数坐标的次刻度标签，关掉次刻度线并不等于关掉其数字。文字边界相交只是定位信号，不能判断结构遮挡、数学排版含义或整体审美；仍须实际查看最终尺寸输出。PDF/SVG 外部改字后再导出检查，不能沿用旧图的审阅结果。

## 反馈如何回到源文件

让用户反馈落到对象和任务：“右侧结构看不出共占据”“步骤顺序容易被理解为确定性成功”“所有刻度字再大一点”。区分科学内容、影响解释的呈现和纯呈现，局部修改源规格并保留已接受修正；然后重查受影响层。无法回写的外部图像编辑标为派生文件。审美建议保留适用条件，单次成功不提升为全局强制风格。


## 材料先行与领域任务覆盖

作者不知道图型是正常入口。先读材料，提出“读者原来怎样理解→希望怎样判断”的几个可纠正候选，用具体草图解释各自强调/隐藏什么，再协作收敛；不要求其先填写完整故事。跨论文先比较问题、对照、证据范围与图件任务，不能把相似外观自动归成同一结论。与 research-harness 的 story-discovery 流程交接，已有 argument-architect 状态时复用主张/证据ID。

总览框架、架构、结构层级、机理、PES切片、网络、能量台阶和定量图分别考虑读者动作。反应网络尤其保留节点身份和边的科学含义；修剪前后位置应便于比较。状态能与过渡态势垒、单个构型与构型集合要分开，不把能量差变成反应峰。高维PES说明投影/切片坐标与被省略自由度。需要复杂源数据编码时可用项目审阅的recipe，而不是把所有结果塞进固定摘要柱图。

模型迁移图、反应网络、表格重排、热图与配对数据图需要不同的转换依据。对每个任务保留来源定位和表示变化；缺少真实过渡态数据时，不将示意台阶称为已复现的能量路径。

## 表格复现不是热图替换

精确查值的数值表与用色标比较模式的热图分别设计和验收；不能因为矩阵格内有数字，就把热图称为原表复现。需要换编码时另列方案，保留源表/源数据，解释阅读任务为何改变。当前NequIP例已分别输出规范数值表ForceTable与另行设计的ForceOrder热图，主对照不再混用。

面向论文交付，按最终物理尺寸核对实际字体、字号/字重、变量/单位、基线/中心线、重复节点尺寸、箭头起止和留白。源图复现逐对象核对数量与坐标层级；JCIM图中的十节点不能随手简化为八节点仍称忠实复现。600dpi只提高导出采样，不补救版式缺陷。已发现明显差距时回到具体对象修正，再打开新PDF检查，不以程序通过或“仅为demo”回避质量要求。
